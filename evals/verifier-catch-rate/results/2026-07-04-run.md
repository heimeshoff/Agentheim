### Compound-reason fixtures — a design note, not a defect

Three fixtures' planted defects sit adjacent to an earlier-ordered check in
`agents/verifier.md`'s check list, because the same code fact (a color stored
as a raw string, or an event/index change) is visible from more than one
check's lens:

- `stale-readme` (planted: check 5) — the new `WidgetRepainted` event is
  simultaneously a new domain term (check 4) *and* the reason the README is
  stale (check 5). All 3 runs cited both; check 5 was always present.
- `missing-adr` (planted: check 6) — the hex-string color representation is
  simultaneously a README contradiction (check 4/5) *and* an undocumented
  decision (check 6). All 3 runs led with check 6 as the primary reason and
  cited check 4/5 as corroborating evidence.
- `index-tampering` (planted: check 7) — the worker's own `## What` framed
  the violation partly as a scope question, so the verifier's REASONS
  consistently cited check 3 alongside check 7.

This was checked empirically (a scout run per previously-unmeasured fixture,
before committing to the full k=3 x 9 matrix) precisely because check 4
(ubiquitous language) sits *before* checks 5/6/6b in `agents/verifier.md`'s
ordered list, raising a real risk that the verifier would stop at check 4
and never reach the intended planted check for `stale-readme`, `missing-adr`,
and `contradicts-adr` — which would have been a genuine fixture-design flaw
requiring correction (mirroring the `clean` v1 fix in v3h6p). It did not
happen: in every run, the verifier's REASONS block named the specific
planted check among its cited reasons (usually as the lead reason, sometimes
as a corroborating one), so all three fixtures scored as catches, right-reason,
not lucky catches. **No fixture correction was needed this pass** — see
`expected.json` files and `diff.patch` files, all unchanged from v3h6p's build.

`contradicts-adr` run 2 did not use the literal string "check 6b" but its
REASONS block is substantively about the same fact `expected.json.check`
names (`paint(color)` storing `String(color)` in direct contradiction of
ADR-0001's mandated `Color` enum, with no superseding ADR) — scored as a
catch, right-reason, per the eval's own scoring rule ("compare free-text
against `expected.json.check`'s description, not the literal check id
string").
