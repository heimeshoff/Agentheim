The layer map

Six layers, top to bottom. The builder talks in phrases; skills orchestrate; agents do focused work; a git-free mechanized layer performs deterministic bookkeeping; everything lands as markdown in .agentheim/ and is committed to git. The dashboard sits beside this stack as a read-only projection that can only launch a Claude session, never write task state. Click a layer to jump to its section.

The loop the builder runs

The in-app Workflow guide (rebuilt in 0.9.1) teaches the tightest mental model: prepare once, then loop between capturing and shipping. Ochre marks the builder's moves, neutral the harness's.

03 · when tasks are ready

Promote & work

Gate: you review todo before launch; the verifier guards every commit.

Any time: whats-next reads the board and writes one advisory file; inquire answers questions read-only; /dashboard launches the projection.

01 · core principles

What is load-bearing

Thirty-one principles the skills, agents, lib and ADRs state or embody. Each names its reason and where it is written down. The tag says whether it should survive any task backend (a) or is an artefact of the current markdown, git, Claude Code or dashboard implementation.

The keystone, in the vision's own words: "the acute pain is an agreeable agent that produces shallow domain work at speed. Every load-bearing feature is a structural defense against exactly that." Non-goals: not a teaching tool, not a general-purpose harness, not autonomous, not stack-prescriptive, not SaaS.

brainstorm

"let's brainstorm" · "start a new project" · "create a vision"

Socratic loop over eight dimensions (purpose, users, problem, domain language, success, non-goals, constraints, BC seeds), one question at a time, then writes vision.md and, when more than one area of concern exists, context-map.md with DDD relationship labels second to plain description.

Flow, artifacts, invariants
  1. Existing vision → ask revise vs extend; read knowledge/index.md and the protocol head so settled decisions are not re-litigated.
  2. Socratic loop; stop when language is shared, non-goals are specific, and the idea can be explained in under a minute.
  3. Write vision.md: Purpose / Users / The problem / What success looks like / Non-goals / Ubiquitous language (seed) / Open questions with (open since YYYY-MM-DD) per bullet (feeds the vacuum guard).
  4. Optional context-map.md; scaffold contexts/<bc>/README.md from the template.
  5. Architecture foundation pass (skipped only on explicit no): create contexts/infrastructure/ unconditionally; run the architect via the orchestrator; emit type: decision tasks routed by the test "if any single BC didn't exist, would this decision still need to be made?"; emit the walking-skeleton spike at the reserved id infrastructure-001-walking-skeleton with the stop-loss clause; when a frontend exists, create design-system/ and the reserved design-system-001-styleguide task. The reserved-id set is closed at exactly these two.
  6. Never commit the architect's ADR drafts from brainstorm; they ride inside decision tasks.
  7. One protocol entry per session; INDEX inserts for every new BC and foundation task; one commit chore(<bc|global>): brainstorm <topic> — vision created|revised|extended.

Cited: ADR-0026, 0028 (§1, §7), 0064, 0065. Scripts: none; ids minted by prose without the classifyTaskId backstop the other minters use.

quick-capture

"capture this" · "just file it" · "brain-dump" · pinned to haiku

The fast sibling of modeling: no questions, no refinement, one raw task per idea straight into backlog/, routed by ubiquitous-language match. When intent is ambiguous, quick-capture is "the cheaper mistake".

Flow and rules
  1. Split multi-idea messages; read only BC READMEs (Purpose + UL), the context map when routing is unclear. Never reads the backlog, INDEXes or protocol.
  2. Route to an existing BC (infrastructure test for cross-cutting concerns); never spawn a BC; honour a user-named BC.
  3. Pick type by heuristic; spikes carry the stop-loss clause.
  4. Write the task with a single placeholder criterion "To be defined during refinement", tags: [captured], empty backlink fields.
  5. INDEX backlog-list insert + count; protocol entry Capture / Captured; commit chore(<bc>): capture <id> — <title> [<id>], one per task.
  6. Re-route after the fact: move file, rewrite context:, fix both INDEXes, keep the original id even if its prefix names the old BC.

Id backstop: classifyTaskId from lib/id-grammar.mjs must return token, else re-mint. Three evals in skills/quick-capture/evals/ (100% with skill vs 77% without, 2026-06-08).

modeling

"I have an idea" · "refine X" · "promote X" · "there's a bug" · dashboard-fired dismiss <id>

The conversational intake with five verbs. REFINE auto-promotes on readiness since 0.9.0 ("ready but awaiting go-ahead is not a state this skill produces anymore"). Owns DISMISS and CONSOLIDATE because the dashboard is read-only and all .agentheim/ markdown belongs to skills.

Before acting, opening flow, resolution rules

Reads vision (missing → offer brainstorm), context map, all BC READMEs, knowledge/index.md, protocol head (~100 lines), the advisory state/whats-next.md (surfaced with age, never auto-picked), all backlog tasks, and for CAPTURE the candidate BC's done/.

Bare invocation: gather backlog via INDEXes; empty → the do-not-self-generate refusal, then the vacuum guard line from lib/vacuum-guard.mjs; non-empty → table of up to 15 oldest-first, ask refine vs new.

Task resolution: exact id; numeric-only across BCs (legacy); keyword or fuzzy substring over title and filename in backlog/ and todo/. DISMISS also scans doing/ and done/ to refuse early. Modes: CAPTURE defaults Facilitator, REFINE defaults Interrogator, PROMOTE and DISMISS are mechanical.

CAPTURE and REFINE

CAPTURE: at most 3–4 follow-ups → route (global-vs-BC-local test; never spawn infra-flavoured BCs) → prior-art lookup via the backlink matcher (score ≥ 2; same task → switch to REFINE) → decide backlog vs todo; convention check (ADR-0059, doctrine surfaces only) and falsifiability classification (ADR-0061) → complex ideas to the orchestrator → write file with confirmed related_adrs, related_research, prior_art → commit.

REFINE: interrogate goal, criteria, dependencies, split, ADR need; classify criteria; second-drift check (ADR-0068: delete the restatement, leave a pointer); delegate to the orchestrator; update the task, create children with depends_on, write ADR; commit model(<bc>): refine <id> — <title> [<id>]; then run PROMOTE wholesale and announce → promoted <id> to todo/.

PROMOTE, DISMISS, CONSOLIDATE

PROMOTE (mechanized, ADR-0038): readiness = at least one concrete criterion, clear scope, dependencies known and met (fail-closed: a depends_on id in no folder blocks); convention check; all-human-eye tasks need the exact "Verification is builder-eye only" note; styleguide gate for frontend tasks. Then node -e "<bootstrap>" promote <id> → manifest {changed, message, verb, id} or {ok:false, code, reason}; git add exactly changed; commit with the manifest message.

DISMISS (ADR-0022, prose): resolve; refuse if in doing/done; cascade set = fixed point over depends_on/blocks across BCs (upstream dependents only); abort if any member is in doing/done; show the table, one confirmation; hard-delete; reconcile INDEX lines and counts per BC (the one sanctioned multi-BC edit), strip dismissed ids from survivors and from ADRs' related_tasks; one protocol entry; commit chore(<bc>): dismiss <set>. Ids never reused.

CONSOLIDATE (ADR-0041, prose, builder-in-loop): never auto-triggered; flagged by whats-next at ~600 README lines; fold superseded narration, merge redundant entries, never silently drop a term or invariant, preserve every backlink (grep each id against disk); commit model(<bc>): consolidate <bc> README.

Cites ADR-0007, 0017, 0022, 0026, 0027, 0028, 0038, 0039, 0041, 0044, 0052, 0059, 0060, 0061, 0064, 0065, 0068.

research

"research X" · "state of the art for" · internal from brainstorm, modeling, work

Delegates to the researcher, then gates the report through the research-reviewer before it is citable. Up to three concurrent researchers (matches MAX_PARALLEL); "produce a report; do not produce an ADR."

Gate loop and link-back
  1. Researcher: breadth (1–3 WebSearch) → depth (WebFetch 3–7 sources) → parallel angles → cross-check → write knowledge/research/<slug>-<date>.md (Question / Summary / Findings / Sources / Open questions). "Not yet citable."
  2. Reviewer with report path, question, iteration only. PASS → ship. SKIP → ship with note. FAIL likely-fixable at iteration 1–2 → re-dispatch the researcher with CHALLENGED_CLAIMS. FAIL at iteration 3 or genuinely-unverifiable → the researcher labels claims ⚠️ UNVERIFIED and adds an "Unverified claims" section; ship.
  3. Link back: task notes and related_research; ADR references; report related_tasks. INDEX: research-local in one BC or research-global at top level.
  4. Protocol Research: [topic] with the review outcome; commit chore(<bc>): research <slug>.

Skip the gate only with a per-run --no-verify or when a report has no checkable claims. Model routing per ADR-0031: researcher sonnet, reviewer opus.

work — the conductor

"start working" · "let's go" · "pick up where you left off" · flags parsed from prose: --no-verify, "run 5 in parallel"

"The conductor (you) never writes code." Loops until todo is empty, picking up mid-run promotions. Carries a Stop hook that heartbeats state/in-flight.json every turn. The 625-line skill is the densest doctrine surface in the repo; its phases are below.

Phase 1 · Recovery and session-start churn

Inspect contexts/*/doing/ and git worktree list --porcelain. One stranded task → resume first (reuse or recreate its worktree). Two or more → ask parallel / sequential / abandon (abandon = move back to todo, prose). Orphan worktrees → surface for disposition.

Human-churn reconciliation (ADR-0066): resolveSinceLastSessionEnd on the protocol head; conductor runs one git log --since … --name-only; parseCommitLog, findUntrailedCommits, partitionUntrailedCommits against eleven known machine commit shapes; the skill judges governed-surface hits (ADR subjects, README runtime surface / UL / key commands); prints one summary line; when flagged, overwrites state/whats-next.md. Never auto-files, never gates.

Phase 2 · Dependency graph, vacuum guard

Read vision, context map, knowledge/index.md (missing → offer scripts/backfill-indexes.ps1), protocol head (~100 lines, passed to workers as recent activity). Scan todo/ and doing/. Ready ⇔ every depends_on id is in some done/; a dangling id blocks (ADR-0038 Ruling A). Cycles → stop and surface. Report "X ready across N contexts, Y blocked on Z".

Vacuum guard (ADR-0064): on zero ready tasks, refuse to self-generate; extract open vision questions with age; write a minimal Work session ended entry; stop. An explicit ask still wins.

Phase 3 · Batch selection

Advisory conflict pre-scan over What / criteria / Notes for shared paths (annotate merge order only). Weigh whats-next.md for ordering among ready tasks. MAX_PARALLEL defaults to 3. "Pick the lowest-numbered unblocked tasks" (stale under random ids). Remediation over diagnosis (ADR-0065): a cheap known-cause fix outranks a same-thread spike, where same thread = shared defect-family tags or a depends_on/blocks/prior_art link; a same-thread remediation stranded in backlog is surfaced with "promote first?", never auto-promoted.

Phase 4 · Dispatch, worktrees, worker prompt
  1. claim id1,id2 '{"parallel":…,"planningAdvisory":…}' → one manifest grouped per BC; race with modeling → {ok:false}, nothing moved. Commit chore(<bc>): batch start [id] [id]. The todo→doing half rides this commit because git worktree add needs committed state (the one deliberate amendment to ADR-0026).
  2. git worktree add -b aw/<id> .worktrees/<id> HEAD per task; link dashboard/node_modules as a junction when the task touches dashboard/; git config core.longpaths true once per session.
  3. Spawn one agentheim:worker per task in one message with the worker prompt template: workspace, task path (already in doing/), BC, README, INDEX, pre-loaded ADR contents, prior-art Outcome excerpts (last 30 lines), research slugs, recent activity, project pointers, nine CRITICAL rules, the strict return format pasted verbatim.
  4. Parse returns: SUCCESS → verification gate; BOUNCED → bounce integration; FAILED → log, remove worktree, task stays in doing/. Re-scan.

Fan-out worst case: MAX_PARALLEL × (1 orchestrator + up to 4 specialists), documented, not enforced.

Verification gate, verdict handling, bounce, salvage

Skip when: not git; --no-verify; type: decision with exactly one changed file that is an ADR. Resolve the test command once per batch per BC (README ## Test command, else package.json / Makefile / pyproject / Cargo / csproj / go.mod, else none). Resolve the ## Runtime surface manifest once per BC (ADR-0036).

Checkpoint: checkpoint <id> '{"fileList":[…],"iteration":N}' with cwd in the worktree → {changed, refused}; changed folds in the vacated doing/ path, refused drops dashboard/dist/; git -C .worktrees/<id> add <changed>; commit wip [<id>] iter N. Diff = git show HEAD. Spawn agentheim:verifier with task path, BC, README, worktree, iteration N of 3, the worker's SUCCESS block, the diff, the pre-resolved test and launch commands.

PASS / SKIP → git authority integration. FAIL iteration 1–2 → in the worktree move done→doing, revert status, clear completed, append ## Verifier note (iteration N), wip commit, re-dispatch into the same worktree; ITERATION_HINT: task-under-specified is treated as iteration 3. FAIL iteration 3 → salvage patch (escalated-iterN), keep worktree and branch, task stays in doing/, surface to the user with history, suggested fix, worktree path, patch path.

BOUNCE (ADR-0037): salvage (bounced), checkpoint only the task file at its backlog/ path, squash-merge, hand-edit INDEX doing→backlog, protocol "Task bounced", commit, teardown.

Git authority (conductor only)
  1. git merge --squash aw/<id> — the conflict detector. Conflict → git reset --hard HEAD (not merge --abort: squash sets no MERGE_HEAD), keep the loser's worktree, surface. Auto-rebase is a named future enhancement.
  2. complete <id> '{summary, duration, verification:"PASS (iteration N)", filesChanged, testsAdded, adrsWritten}' (or {skipped, skipReason}) — idempotent: the squash already moved the file, so the mover sees done/ and skips to bookkeeping.
  3. ADR finalization first: finalizeAdrNumbering renames provisional numbers against main; index inserts and bidirectional backlinks by hand; ADR summary line ≤ ~60 words.
  4. Enumerated git add of the manifest plus backlink files; commit with the manifest message verbatim <type>(<bc>): <summary> [<id>].
  5. Teardown: unlink the node_modules junction first (removing the worktree with the junction in place deletes the real node_modules), git worktree remove --force, git branch -D.

  9. Three-layer bookkeeping (ADR-0038)

Layer 1 · mover

applyTaskMove(root, id, from, to, {policy, expectedMtimeMs}). Validates the move, resolves the file, checks the optimistic mtime, checks dependencies when moving to todo, rewrites status:, writes the destination (backfilling a missing folder), then unlinks the source (ADR-0055). Layer 3 · skill

Supplies judgment inputs (readiness, batch composition, summaries), runs the verb through the node -e bootstrap, then git add exactly the manifest's changed plus its own files and commits with the manifest's message. Never git add -A.

07 · dashboard and bridge

A read-only projection that can only launch sessions

A stdlib Node server over the project's .agentheim/, a React 18 + htm frontend bundled by esbuild into a committed dist/, and an optional VS Code extension that turns a button click into a real claude terminal. It knows the folder names, the frontmatter, the command strings and the state-file schemas, and nothing else about the workflow.

Runtime

Process model (ADR-0002, 0004)

/dashboard → resolve-launcher.mjs → launch.mjs spawns serve.mjs detached with cwd = os.tmpdir() (so a long-lived process never locks the project directory on Windows) and AGENTHEIM_ROOT in the environment. Binds 127.0.0.1 only. Port is deterministic: 41000 + sha256(root) mod 1024, sticky via last-port.json, with a ladder of eight on collision, so the origin-keyed localStorage stores survive relaunch. Runfile runtime.json gates liveness by pid. Stop kills the pid (Windows: taskkill /F /T). No auto-open of the browser (removed in aw-032; the command text still claims it).

Bundle (ADR-0003, 0005, 0008, 0009)

build.mjs runs esbuild once: entry app/app.js, ESM, minified, bundling React 18.3.1, react-dom, htm 3.1.1 (no JSX anywhere), marked 12, canvas-confetti; copies the styleguide's token CSS byte-for-byte and the vendored Inter Tight and JetBrains Mono latin woff2 subsets. dist/ is committed and derived. The styleguide canvas itself is buildless via import map. Runtime dependencies: none; devDependencies exist only for build and jsdom tests.

The bridge (ADR-0018)

A VS Code extension (not on the marketplace; built with vsce, version 0.5.0) walks up from the workspace to find .agentheim/, binds 127.0.0.1:31425 (ladder 31426, 31427) with a per-activation random token, and writes bridge.json. GET /health is the authoritative capability handshake (prompt, skipPermissions, name, model; absent → legacy baseline). POST /run {prompt, skipPermissions?, name?, model?} (≤ 64 KB, token header, timing-safe compare) opens createTerminal({name, cwd: root, shellPath: claude, shellArgs}) with argv -n <name> [--model <alias>] [--dangerously-skip-permissions] <prompt>; the terminal is the claude process. The dashboard probes discovery → health (800 ms) → run and falls back to the clipboard on any failure, silently; the clipboard path can never carry the bypass flag.
